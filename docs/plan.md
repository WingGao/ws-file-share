# WS下载器

Go 服务端与 CLI，配合单 HTML 下载客户端。实现与启动说明见 `readme.md`，传输消息格式见 `docs/protocol.md`。

## 服务端

- 使用 Go 实现。
- 启动时自动加载本地配置 `config.yaml`。
- WebSocket 提供客户端下载、目录树查询和下载控制能力；文件内容直接通过 WS 二进制消息发送，不封装 HTTP 下载流量。
- 程序提供 HTTP 页面入口，客户端为单个 HTML 文件，可内嵌到服务端分发。
- HTTP API 用于 CLI 管理，包括通知服务端重载配置；不改为 WS。
- 由 Caddy 等反向代理提供对外 HTTPS/WSS，并负责 TLS 证书申请、加载及续期。程序仅监听 HTTP/WS，不生成、读取或管理证书。
- 下载默认监听 `127.0.0.1:8080`，管理使用独立回环端口 `127.0.0.1:8081`，通过 `admin_listen` 配置；CLI 默认通过该本机 HTTP 管理接口通知重载，下载端口不提供管理接口，反向代理只转发下载端口。
- 当前不提供 Token 认证。

## CLI

- `cli add /localdir`：添加目录，返回 `md5(absolute_path)` 作为资源 ID，持久化到 `config.yaml`，通过 HTTP API 通知服务端重载。
- `cli add /localfile.zip`：支持添加单个文件。
- CLI 管理通信使用 HTTP/HTTPS，不改为 WS。

## 客户端

- 使用单个 HTML 页面，包含所需的 JavaScript 和样式，替代 Python/uv 客户端。
- 页面提供服务地址（对外 `wss://host`，本地开发 `ws://127.0.0.1:8080`）、资源 ID、保存目录选择和允许覆盖选项；根据页面的 HTTP/HTTPS 地址自动选择 WS/WSS。
- 用户点击选择保存目录并授予读写权限，通过 File System Access API 创建目录、读取和写入文件。
- 不能直接以本地绝对路径字符串授予写入权限；保存位置由浏览器目录选择器确定。
- 再次打开页面时，允许重新选择原保存目录，直接从磁盘上的分块和记录恢复下载，不依赖浏览器缓存保存唯一断点。
- 允许覆盖选项对应原先的 `--overwrite` 语义。
- 保留资源本身的名称：目录 `/data/photos` 保存到 `out/photos/...`，文件 `/data/a.zip` 保存到 `out/a.zip`。
- 获取一次目录树后，由客户端决定下载哪些文件及分块；无需持续更新目录树。
- 不处理下载期间源文件的新增、修改或删除，不提供源文件版本检查或一致性快照保证。

## 软链接

- 下载软链接指向的真实文件或目录内容，客户端创建普通文件和目录，不创建系统软链接。
- 文件或目录保留链接所在位置的名称，实际内容来自服务端解析后的目标。
- 允许解析目录内、目录外和绝对路径目标，不增加链接目标范围限制。
- 服务端生成目录树及读取内容时解析链接；对无法解析的循环链接、失效链接或目录递归环明确报错并跳过相应条目，避免无限遍历。

## 分块传输

- 由客户端主动请求需要的块，服务端按请求读取和发送，不主动调度下载块。
- 默认块大小为 4 MiB（4 × 1024 × 1024 字节），最后一块允许不足 4 MiB。
- 每个块对应一条 WS 二进制消息，包含请求标识、块定位信息及文件数据；允许 WS 库在底层将消息分成多个帧，不要求一个块必须对应一个帧。
- 客户端默认最多保持 8 个未完成的分块请求，接收并写入一个块后可继续请求其他块，不等待整批完成。
- 服务端最终通过单一发送循环写入每条 WS 连接。
- 块大小和客户端未完成请求数支持配置。

## 每条 WS 通道的容量限制

- 默认文件数据预算为 32 MiB，覆盖当前通道正在读取、排队及正在写入 WS 的文件数据，所有下载请求共享。
- 读取块之前先申请对应字节数的容量，容量不足时等待，不提前读取文件内容。
- 块消息写入 WS 完成后释放容量；发送失败或取消时也必须释放。
- 此预算限制服务端应用层文件数据缓冲，不代表系统网络缓冲或客户端未接收数据的总上限，也不是进程总内存上限。
- 限制待处理请求数量，避免请求队列无限增长。
- 通道容量支持配置，且必须能够容纳至少一个最大块。

## 断点续传与完整性校验

- 客户端记录已完成的块，恢复下载时只请求缺失或校验失败的块。
- 分块文件和下载记录直接保存在目标文件同级，不创建专用目录。例如目标为 `a.zip`，分块文件为 `a.zip.0._part`、`a.zip.1._part` 等，下载记录为 `a.zip._part.json`。
- 下载记录包含资源和文件定位信息、文件大小、块大小及已完成块的校验信息，用于恢复和核验。
- 每块进行完整性校验，写入独立分块文件并成功关闭可写流、提交文件内容后，才记录为已完成；不能仅凭 `write()` 返回就确认断点。
- 全部块完成并校验通过后，按顺序流式合并写入正式目标文件，不将整个文件加载到内存，也不依赖本地文件重命名 API。
- 正式目标文件的可写流成功关闭并确认合并结果正确后，才清理分块文件和下载记录。
- 合并中断时保留分块，下次可重新合并，不需要重新下载已校验的块。
- 发生异常退出后，恢复下载时核验本地已完成块及断点记录。
- 不因源文件变化而主动废弃已有断点，不承诺跨源文件修改的下载结果保持一致。

## 平台支持

- 服务端、CLI 和客户端均支持 Windows、Linux、macOS。
- HTML 客户端以桌面 Chrome、Edge 为支持范围，页面检测目录读写 API，不具备所需能力时提示使用支持的浏览器。

## 同名文件处理

- 目标位置存在同名文件时，校验内容一致则跳过。
- 校验不一致时默认报错；仅勾选页面的允许覆盖选项时允许覆盖。
- 覆盖时先下载并校验所有分块，再合并写入目标文件；成功提交并校验完成之前保留分块。
